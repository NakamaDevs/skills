# ASD-STE100 Technical English

Use a practical communication profile based on ASD-STE100 Issue 9. Make technical content clear without changing its meaning.

## Select the mode

- Use **practical STE** by default. Apply the concise rules below without claiming formal compliance.
- Use **strict STE review** only when the user requests compliance, validation, or rule citations. Read [references/issue-9-profile.md](references/issue-9-profile.md) and consult the official Issue 9 dictionary.
- Use **light edit** when the user asks to preserve their voice. Fix only clear readability problems.

State the mode only when it helps the user understand the result.

## Apply the practical profile

1. Lead with the result, request, decision, or important fact.
2. Use active voice. Use passive voice only when the agent is unknown or unimportant.
3. Keep each sentence to 20 words or fewer when possible.
4. Put only one instruction, subject, or main idea in each sentence.
5. Keep each paragraph to one topic and six sentences or fewer.
6. Use simple present, simple past, simple future, infinitive, or imperative verb forms.
7. Use imperative verbs for instructions.
8. Use one term for one item, action, or concept. Do not change terms only for variety.
9. Prefer short, common words. Avoid idioms, slang, jargon, phrasal verbs, and Latin abbreviations.
10. Keep multi-word nouns to three words or fewer when possible.
11. Use a vertical list when it makes complex information clearer.
12. Do not use semicolons. Divide the text into separate sentences.
13. Use inclusive and gender-neutral language.

The 20-word limit is a deliberate default for short communication. Issue 9 permits 25 words in descriptive text.

## Preserve technical meaning

Keep these items exact unless the user asks for a change:

- Code, commands, API routes, identifiers, function names, and file paths
- Product names, official terms, approved terminology, and acronyms
- Dates, numbers, prices, units, versions, status values, and error text
- Links, citations, quoted text, and contract or policy language

Do not invent an agent to remove passive voice. Do not replace a technical term with a simpler but inaccurate term.

If a source term conflicts with the controlled dictionary, preserve it as an approved technical term when context supports this choice.

## Rewrite without losing information

1. Identify the purpose and the required outcome.
2. Mark all facts and exact technical items that must remain unchanged.
3. Rewrite the structure, not only individual words.
4. Divide long sentences and dense paragraphs.
5. Remove repetition and filler that add no meaning.
6. Compare the rewrite with the source for omissions or changed meaning.
7. Return only the rewrite unless the user requests commentary or a compliance report.

For reviews, give the improved text first. Then list material issues with the applicable rule when requested.

## Resolve conflicts

- Accuracy has priority over shortness.
- User instructions and required formats have priority over this style profile.
- Legal, safety, policy, and quoted language stays exact when a rewrite could change its effect.
- Code blocks and machine-readable content do not obey prose sentence limits.
- A requested personal voice can include natural phrasing unless it causes ambiguity.

When another communication skill applies, use that skill for audience, tone, and message purpose. Use this skill for language clarity.

## Check the result

Before delivery, confirm that:

- The first lines give the main point.
- Each sentence has one clear purpose.
- Pronouns have clear antecedents.
- Terminology stays consistent.
- Exact technical items did not change.
- The rewrite keeps all important facts, decisions, risks, and requests.
- The result does not claim formal ASD-STE100 compliance without a dictionary-based review.
